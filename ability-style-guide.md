# Into the Wild — Ability Style Guide

## Purpose

This document defines the writing style and formatting conventions used for card abilities.

Gameplay rules are defined in **core-game-engine.md**.

Card structure is defined in **card-specification.md**.

This guide ensures that all abilities are written consistently and interpreted the same way by players.

---

# Design Principles

Abilities should be:

- Clear
- Concise
- Unambiguous
- Self-contained

Avoid unnecessary flavor text inside abilities.

Flavor belongs in the card's facts, not its mechanics.

---

# Writing Style

Write abilities using imperative language.

Good examples:

```
Draw 1 card.
```

```
Exhaust this card.
```

```
Restore 1 Water Energy.
```

Avoid conversational wording.

Avoid describing why something happens.

Describe only what happens.

---

# One Effect Per Line

Each bullet should describe one effect.

Good

```
- Draw 1 card.
- Exhaust this card.
```

Avoid

```
Draw 1 card and Exhaust this card.
```

unless both actions always happen together.

---

# Targeting

Always identify the target.

Examples

```
One Habitat you control
```

```
One opposing Habitat
```

```
All Energy cards
```

```
Each player
```

Avoid vague wording like

```
a card
```

---

```

```

```

```

```

```

```

```

```

---

# Numbers

Always use numerals.

Good

```
Draw 2 cards.
```

Not

```
Draw two cards.
```

---

# Card References

Refer to cards by their type.

Examples

```
Habitat Card
```

```
Energy Card
```

```
Event Card
```

Do not reference artwork or flavor text.

---

# Energy References

Always capitalize Energy types.

Examples

```
Water Energy
```

```
Flora Energy
```

```
Fauna Energy
```

---

# Rank References

Always refer to:

```
Printed Rank
```

or

```
Effective Rank
```

Never simply say

```
Rank
```

when the distinction matters.

```

---

# Design Principles

When creating abilities:

- Keep wording as short as possible.
- Use existing keywords whenever possible.
- Do not redefine existing terms.
- One keyword should have one meaning throughout the game.
- Prefer consistent wording over creative wording.
